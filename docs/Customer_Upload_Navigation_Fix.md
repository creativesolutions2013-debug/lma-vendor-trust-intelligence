# Pending uploads across stage navigation

An automated customer-journey diagnostic found that uploaded originals could disappear before the first evaluation. Navigating away from Upload evidence remounts the native picker empty on return. Its empty callback cleared the separate pending-file store. The UI could briefly still show the pending files, but the subsequent evaluation and completed package contained no evidence artifacts. A real browser exported that empty manifest; an actual-app native empty-picker replay reproduced the state loss.

The correction keeps pending originals when the picker reports an empty value. New selections still add files. The existing **Discard new file selections** action removes pending selections; **Clear this assessment** removes the whole assessment. The upload caption makes those actions explicit. No new controls, parsing rules, thresholds or confirmation behavior were added.

The regression uploads two synthetic sources through the native widget, applies metadata, navigates before initial evaluation, replays the empty picker callback and verifies the originals and dates survive. It then evaluates, records a finding, completes and checks the exported originals and provisional safeguards. Reopening and explicitly discarding another pending selection preserves already evaluated evidence.

A fresh Chromium run after restarting the server completed upload, navigation, evaluation, finding creation/duplicate rejection, completion, reopening, metadata change, explicit reevaluation and starting another assessment. Three completed packages each contain two exact uploaded originals, 13 resolving manifest quotations, six source-bound unconfirmed fact quotations and one unresolved ENC-01 finding. Residual score remains null and vendor approval false. A metadata change blocks stale exports; the new assessment intake is empty.

[Machine-readable observations](../benchmarks/observations/customer_pending_upload_navigation_1.json) bind the tested module, sources and local evidence bundle by SHA-256. The local bundle retains screenshots, DOM text, downloaded packages, runner and verification script. An intermediate replay still used the old loaded server module and reproduced the failure; it is retained separately and not counted as a fixed-module trial.

This is one successful fixed browser journey with two new synthetic TXT files, not human usability/time-savings measurement, population reliability, independent TPRM validation or external holdout accuracy. Live application dates differ from the fixed benchmark. No benchmark corpus, annotations, metrics, extraction rules, production authentication, main or PR #21 were changed.
